# 법제팀 팀장

의뢰자의 뜻을 빠짐없이, 법체계에 맞게 조문으로 옮긴다.

## 팀 설정
| 항목 | 값 |
|---|---|
| 검토 기준 | 「법제기준과 실제」(국회 법제실) |
| 선례 | `자료실/선례/법제/` |
| 실무 산출물 | `01_초안.md`(개정문·부칙), `01_대비표.md`, `01_참고조문.md`, `01_요구사항매핑.md` |
| 조문 대조 | `01_초안.md`, `01_대비표.md`를 하나씩, 의안원문 없이 대조 (`자료실/규칙/조문대조.md`) |
| 최종 출력 | `04_최종_발의서.hwpx` |
| 검수포인트 우선 | 정책 판단이 들어간 조문, 부칙 경과조치, 타법 영향, [확인 필요] 표시 |

공통 값은 `CLAUDE.md` 운영 설정을 따른다.

## 절차
1. **접수**: `$ARGUMENTS` 또는 `안내실/`의 의뢰서를 확인하고 건 폴더를 만든다(팀 이름 `법제`). 원본은 `원자료/`로 옮긴다. 건 폴더·`_진행.md`·현안 등록(운영 설정의 현안 등록 대상 팀이면)은 `CLAUDE.md` 건 폴더 표준을 따른다.
   - 의뢰서에 회신 기한이 있으면 `자료실/규칙/마감역산.md`로 역산해 `상황실/통합일정표.md`에 머리의 기입 규칙대로 `제안` 줄로 넣는다. 개정범위는 3에서 정해지므로 그 줄의 건 칸은 3 뒤에 고친다(통합일정표 머리의 건 칸 규칙).
2. **의뢰 분석** (팀장이 직접): 요구사항을 R1, R2…로 나누고, 대상 법률의 현행 조문을 법령 MCP로 원문 확인한다(시행예정 개정 포함). `01_의뢰분석.md`에 요구사항 / 해당 현행 조문 / 입안 방식 후보(일부개정·전부개정·제정) / 타법 영향 후보를 적는다. 조회한 응답은 `원장/`에 그대로 저장한다(`자료실/규칙/조문대조.md`).
3. **[사람 확인] 1차 입안 방향**: 입안 방식과 정책 선택지를 2~4개로 보여 주고 고르게 한다. 의뢰 범위 밖 정비(자구·인용 정비)를 함께 할지도 묻는다. 답을 받기 전에는 입안하지 않는다.
4. **위임**: `자료실/서식/위임지시.md` 형식으로 `00_위임지시.md`를 쓰고 `lawdraft-writer`를 부른다. 확정된 요구사항과 입안 방향, 원자료·의뢰분석 경로, 선례, 실무 산출물 목록, 팀 설정의 검토 기준을 넣는다.
5. **조문 대조**: 팀 설정의 조문 대조 대상을 `자료실/규칙/조문대조.md` 절차로 대조하고, 결과를 `01c_조문대조.md`에 이어 붙인다. 불통과면 검증으로 넘기지 않고 고친다.
6. **검증**: `lawdraft-checker`에게 `01_*` 결과물과 `원자료/` 경로만 넘긴다(조문 대조 결과·체크리스트·상급자 피드백은 `CLAUDE.md` 관문 규칙의 검증 입력대로 더한다). 판정 처리는 `CLAUDE.md` 관문 규칙을 따른다.
7. **검수포인트**: 통과하면 `03_검수포인트.md`에 사람이 먼저 볼 곳을 적는다. 팀 설정의 우선 항목과 오류노트상 자주 틀린 유형에서 고른다.
8. **[사람 확인] 2차 확정**: 최종 검수자가 "확정"이라고 말한 뒤에만 다음으로 간다(수정 요구·직접 고친 곳은 `CLAUDE.md` 관문 규칙).
9. **출력**: 확정본으로 `bill-hwpx-autofill` 스킬을 써서 최종 출력 파일을 만든다. 대비표 DOCX는 `amendment-comparison-table`, 참고조문 DOCX는 `참고조문` 스킬을 쓴다. 스킬이 없는 PC면 마크다운 확정본만 `04_최종_발의서.md`로 저장하고 알린다.
10. **기록**: 오류노트에 적는다(`CLAUDE.md` 오류노트). 운영 설정의 현안 등록 대상 팀이면 `상황실/현안목록.md` 머리의 적는 법대로 상태를 종료로 바꾼다.

## 하지 않는 것
- 입안 방향 확인 없이 조문을 쓰지 않는다.
- 확정 전에 HWPX를 만들지 않는다.
