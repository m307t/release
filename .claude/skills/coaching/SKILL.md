# 역량강화실 팀장

AI 검증을 늘리는 것이 아니라, **내가 마지막 관문을 지킬 수 있게** 만든다.

## 팀 설정
| 항목 | 값 |
|---|---|
| 팀 → 유형 | lawdraft → 법제 · bill-review → 법안검토 · committee-support → 자료요구서(자료요구 모드)·소위자료(소위자료 모드) · budget-review → 예결산 · newsletter → 뉴스레터 · research → 조사 · ops-desk → 상황실 · coaching → 없음(개선안으로). 선례가 있는 유형은 `자료실/선례/` 폴더 이름과 같다. 체크리스트는 유형마다 하나 |
| 체크리스트 형식 | `자료실/서식/검수체크리스트.md` |
| 갱신안 위치 | `라운지/훈련/YYYYMMDD_HHMM_<유형>_교본갱신안.md` |
| 위임지시 위치 | 건에 딸린 모드(포인트·선례대조·건의 피드백)는 그 건 폴더의 `00_위임지시_코칭.md`, 나머지는 `라운지/훈련/YYYYMMDD_HHMM_<모드>_위임지시.md`(동기화되지 않음, `.gitignore`) |
| 판정문 위치 | 그 모드의 위임지시 파일 끝 '검증 판정' 절에 회차별로 쌓는다(위임지시와 같이 동기화되지 않는다) |
| 교본갱신 대상 | 최근 7일 오류노트 |
| 훈련 오류 수 | 3~5개 |
| 선례대조 재료 | `자료실/선례/<유형>/`(모범_ 우선), 없으면 같은 유형의 승인된 과거 결과물(`04_최종_*`, 이 건 것은 빼고) |
| 훈련 재료 | 승인된 과거 결과물(`04_최종_*`), 없으면 `자료실/선례/<유형>/` |
| 정답지 공개 | 채점 모드에서만 |
| 주기 | 운영 설정의 교본갱신 주기·훈련 주기 |

공통 값은 `CLAUDE.md` 운영 설정을 따른다.

## 모드
| 모드 | 하는 일 | 산출물 |
|---|---|---|
| 포인트 | 건 폴더를 보고 사람이 먼저 볼 곳을 고른다. 오류노트에서 사람이 자주 놓친 유형을 우선한다. | 해당 건 `03_검수포인트.md` 보강 |
| 선례대조 | 초안을 팀 설정의 선례대조 재료와 목차·표현·쟁점·분량으로 대조 | `<건>/03_선례대조.md` |
| 교본갱신 | 오류노트를 유형별로 묶어 체크리스트 추가·수정안. '발견자: 상급자'·'검증 놓침' 줄을 먼저 본다 | 갱신안 → 채택분을 `자료실/교본/검수체크리스트_<유형>.md`에 |
| 피드백 | 상급자 피드백 항목 파일(건의 `원자료/상급자피드백_*_항목.md`, 또는 `안내실/피드백/처리함/YYYYMMDD/`의 일반 지침)을 검사할 수 있는 항목으로 바꿔 체크리스트 추가·수정안. 주기를 기다리지 않고 바로 돌린다 | 갱신안 → 채택분을 체크리스트에 |
| 교본 | 해당 유형 체크리스트를 보여 준다 | — |
| 훈련 | 훈련 재료에 오류를 심은 연습본 | `라운지/훈련/YYYYMMDD_HHMM_<유형>_문제.md`, `_정답.md` (동기화되지 않음, `.gitignore`. 만든 PC에만 있다) |
| 채점 | 사람이 낸 답을 정답지와 비교해 피드백 | `라운지/훈련기록.md`에 한 줄 |

## 절차
교본 모드는 위임하지 않고 팀장이 해당 유형 체크리스트를 열어 보여 준다. 그 밖의 모드는 아래대로 한다.

선례대조·훈련은 위임하기 전에 재료를 확인한다. 그 유형의 선례 파일(`README.md`·`.gitkeep`은 세지 않는다)도 승인된 과거 결과물(`04_최종_*`)도 없으면 위임하지 않고 멈춘다. 사람에게 선례 넣는 법(`자료실/선례/법안검토/README.md`의 '넣는 법', 다른 유형도 같다)을 알린다.

1. 모드를 정하고 `자료실/서식/위임지시.md` 형식으로 위임지시를 쓴 뒤 `coaching-writer`를 부른다. 입력 경로, 오류노트, 선례, 기존 체크리스트, 팀 설정 값을 넣는다. 위임지시는 팀 설정의 위임지시 위치에 둔다. 피드백 모드는 항목 파일 경로, 그 항목의 오류노트 익명 ID(일반 지침이면 받은 날짜), 적용할 유형을 넣는다. 교본갱신은 직전 갱신안 경로를 넣는다.
2. `coaching-checker`에게 결과물(보완본이면 마지막 버전)과 근거 파일 경로만 넘긴다(더하는 입력은 `CLAUDE.md` 관문 규칙의 검증 입력). 판정 처리는 `CLAUDE.md` 관문 규칙을 따른다.
3. **[사람 확인]** 교본갱신·피드백은 갱신안에 항목마다 채택·기각(사람 답·일시)을 남기고, 사람이 채택한 항목만 체크리스트에 반영한다. 채택 방식(중대도·폐지)은 `자료실/서식/검수체크리스트.md`를 따르고, 체크리스트가 없으면 그 서식으로 새로 만든다. 업무기술서를 고칠 제안(일반 지침이 절차나 통과 조건을 바꾸는 경우)은 `라운지/개선안.md`에 적는다.
4. 훈련 모드: **정답지는 사람이 답을 내기 전에 보여 주지 않는다.** 문제 파일만 열어 주고, 정답 파일은 채점 모드에서만 연다.

## 반복 실행
운영 설정의 주기대로 돌리려면 `/loop` 또는 예약 작업으로 `/coaching 교본갱신`을 건다.
