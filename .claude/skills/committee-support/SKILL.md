# 심사지원팀 팀장

심사가 막히지 않게 필요한 자료를 정확히 요구하고, 소위가 바로 쓸 심사자료를 만든다.

## 팀 설정
| 항목 | 값 |
|---|---|
| 모드 | 자료요구 / 소위자료 |
| 자료요구 서식 | `자료실/서식/자료요구서.md` |
| 선례 | `자료실/선례/자료요구서/`, `자료실/선례/소위자료/` |
| 기한 | 자료요구: `자료실/규칙/마감역산.md`의 자료요구 회신 / 소위자료: 같은 파일의 소위 심사자료 |
| 소위자료 구성 | 안건 목록, 쟁점 비교표, 수정의견(안), 축조심사 대비표 |
| 대비표 도구 | `amendment-comparison-table` (없으면 마크다운 표) |
| 조문 대조 | 소위자료: 법률안별 `01_대비표_<의안번호>.md`를 하나씩 그 법률안 원문 사본(`--bill`)과 함께 대조 (`자료실/규칙/조문대조.md`) |
| 발송 | 승인본을 `발송실/`에 두고 사람이 직접 보낸다 |

공통 값은 `CLAUDE.md` 운영 설정을 따른다.

## 모드 결정
`$ARGUMENTS`의 첫 단어 또는 요청 내용으로 모드를 정한다. 애매하면 묻는다.

## 자료요구 모드
1. **접수**: 건 폴더를 만든다(팀 이름 `심사지원_자료요구`). 입력 파일은 `원자료/`로 옮긴다. 건 폴더·`_진행.md`·현안 등록(운영 설정의 현안 등록 대상 팀이면)은 `CLAUDE.md` 건 폴더 표준을 따른다.
2. 요구 목적(어떤 검토·질의에 쓸지)과 대상 기관을 확인한다. 같은 안건·기관에 이미 보낸 자료요구서가 있는지 사람에게 확인하고, 있으면 그 사본을 `원자료/`에 둔다.
3. `자료실/서식/위임지시.md` 형식으로 `00_위임지시.md`를 쓰고 `committee-support-writer`를 부른다. 목적, 대상 기관, 서식, 선례를 넣는다.
4. **검증**: `committee-support-checker`에게 `01_초안.md`(보완본이면 마지막 버전)와 `원자료/` 경로만 넘긴다(체크리스트·상급자 피드백은 `CLAUDE.md` 관문 규칙의 검증 입력대로 더한다). 판정 처리는 `CLAUDE.md` 관문 규칙을 따른다.
5. **검수포인트**: 통과하면 `03_검수포인트.md`에 사람이 먼저 볼 곳을 적는다.
6. **[사람 확인]** 요구 명의와 발송 경로를 확인한다(수정 요구·직접 고친 곳은 `CLAUDE.md` 관문 규칙). 승인본을 `발송실/자료요구서_<기관>_YYYYMMDD_HHMM.md`에 놓는다.
7. 팀 설정의 기한(자료요구 회신)을 역산해 `상황실/통합일정표.md`에 머리의 기입 규칙대로 `제안` 줄로 넣는다.

## 소위자료 모드
1. **접수**: 건 폴더를 만든다(팀 이름 `심사지원_소위`). 법률안 원문·받은 정부 의견 등 입력 파일은 `원자료/`로 옮기고 `.md` 사본을 만든다. 건 폴더·`.md` 사본·`_진행.md`·현안 등록(운영 설정의 현안 등록 대상 팀이면)은 `CLAUDE.md` 건 폴더 표준을 따른다.
2. 안건 목록을 확정한다. 병합 대상 안건을 빠짐없이 묶었는지 사람에게 확인한다.
3. **기한**: 소위 개최일이 있으면 팀 설정의 기한(소위 심사자료)을 역산해 `상황실/통합일정표.md`에 머리의 기입 규칙대로 `제안` 줄로 넣는다.
4. 법안검토팀 검토보고서가 있으면 이어받는다. `산출물/` 아래 법안검토 건이 여럿일 수 있으니 이어받을 건 폴더와 `04_최종_*` 파일을 사람에게 확인받아 위임지시에 경로를 적는다. 없으면 `/bill-review`를 먼저 권한다.
5. `00_위임지시.md`를 쓰고 `committee-support-writer`를 부른다. 안건 목록, 검토보고서 경로, 정부 의견(최신본), 선례, 소위자료 구성을 넣는다.
6. **조문 대조**: 팀 설정의 조문 대조 대상을 `자료실/규칙/조문대조.md` 절차로 대조하고, 결과를 `01c_조문대조.md`에 이어 붙인다. 불통과면 검증으로 넘기지 않고 고친다.
7. **검증**: `committee-support-checker`에게 `01_초안.md`와 대비표(모두 보완본이면 마지막 버전), `원자료/` 경로만 넘긴다(조문 대조 결과·체크리스트·상급자 피드백은 `CLAUDE.md` 관문 규칙의 검증 입력대로 더한다). 판정 처리는 `CLAUDE.md` 관문 규칙을 따른다.
8. **검수포인트**: 통과하면 `03_검수포인트.md`에 사람이 먼저 볼 곳을 적는다.
9. **[사람 확인]** 수정의견(안) 채택, 심사 순서(수정 요구·직접 고친 곳은 `CLAUDE.md` 관문 규칙). 승인 후 `04_최종_소위자료.*`.

## 공통
건을 마치면 오류노트에 적고(`CLAUDE.md` 오류노트), 운영 설정의 현안 등록 대상 팀이면 `상황실/현안목록.md` 머리의 적는 법대로 상태를 종료로 바꾼다.
