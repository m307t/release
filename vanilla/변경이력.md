# 변경이력

업무기술서·규칙·설정을 바꿀 때마다 한 줄 적는다. 줄 단위의 자세한 차이는 git 기록(`git log -p <파일>`)에 남고, 줄을 넣은 커밋은 `git blame 변경이력.md`로 찾는다.

적는 법:
- 바뀐 것: 무엇을 어떻게 바꿨는지 120자 안팎 한 문장으로 쓴다. 세부는 커밋 메시지에 둔다.
- 고친 파일: 5개까지 적고, 넘으면 '외 N'으로 쓴다.
- 요청·근거: 사람 지정 / 점검·검토 결과 / 일하다 생긴 불편 가운데 하나를 쓴다. 저장소에 없는 문서의 ID나 번호는 적지 않는다.
- 날짜는 한국 시각으로 쓴다.
- 이미 있는 줄을 고치거나 지울 때는 `README.md` 매일 동기화의 규칙을 따른다.
