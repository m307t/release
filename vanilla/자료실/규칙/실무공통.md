# 실무 공통 규칙

모든 실무 에이전트(`*-writer`)는 작업 전에 이 문서를 읽고 따른다.
여기 있는 내용은 각 에이전트 파일에 다시 쓰지 않는다. 바꿀 때는 이 문서만 고친다.

## 시작
1. 팀장이 알려 준 위임지시 파일(보통 건 폴더의 `00_위임지시.md`)을 먼저 읽는다. 범위·분량·형식·작업 폴더·산출물 경로는 위임지시를 따른다.
2. `CLAUDE.md`의 운영 설정과 `자료실/규칙/`의 출처등급·표기규칙·마감역산을 따른다.
3. 위임지시에 적힌 선례를 읽는다. 파일명이 `모범_`으로 시작하는 선례를 먼저 본다. 선례와 서식이 다르면 선례를 따른다.

## 작성
- 원문으로 확인하지 못한 내용은 `[확인 필요: 사유]`로 표시한다. 추측으로 채우지 않는다.
- 사람이 정할 선택지는 정하지 말고 `[판단 필요: 선택지]`로 남긴다.
- 법령·조문은 기억이 아니라 법령 MCP 원문으로 확인한다. 시행예정 개정도 확인한다.
- 법령 MCP로 조문을 조회하면 응답을 작업 폴더의 `원장/`(보통 건 폴더, 선행 조사는 `조사/원장/`)에 그대로 저장한다. 형식은 `자료실/규칙/조문대조.md`.
- 근거를 인용할 때는 출처등급 표기(`[A-1]`)를 쓴다.
- `원자료/`의 파일은 고치지 않는다.

## 중립
- 안을 구분할 때는 의안번호나 대표발의자 이름(○○의원안)만 쓴다. 정당 이름으로 입장을 나누지 않는다.
- 정당·인물을 평가하는 표현, 근거 없는 평가어(과도한, 부당한, 졸속 등)를 쓰지 않는다. 평가가 필요하면 근거를 대고 "~할 필요가 있음", "~라는 의견이 있음"처럼 쓴다.
- 찬반이 갈리는 쟁점은 양쪽 근거를 함께 적는다. 한쪽 자료만 찾았으면 `[확인 필요: 반대 근거 미확보]`로 남긴다.

## 보완 회차
- 검증 보완이면 검증 지적사항만 고친다.
- 사람·상급자 요구로 되돌린 것이면 위임지시 '사람이 정한 것'에 이번에 더해진 요구·F번호만 고친다.
- 그 밖의 부분은 바꾸지 않는다.
- 새 버전으로 저장한다(`01_초안_v2.md`, `_v3`). 맨 위에 보완 내역 표(지적 번호 또는 F번호 / 고친 곳 / 고친 내용)를 단다.
- 건 폴더가 없는 상황실은 작업 파일 이름 끝에 `_v2`·`_v3`를 붙인다(예: `…_뉴스_브리핑_v2.md`). 첫 줄 형식이 정해진 결과물(뉴스 브리핑)은 보완 내역 표를 파일 맨 끝(검색 기록 뒤)에 둔다.

## 보고
끝나면 만든 파일 경로와 `[확인 필요]`·`[판단 필요]` 개수만 짧게 보고한다.

## 보안
의뢰 내용·미공개 자료는 외부 검색어에 넣지 않는다. 메일 발송·일정 등록·게시를 하지 않는다(게시의 범위는 `CLAUDE.md` 보안).
