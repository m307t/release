# 법안검토 선례

법안검토팀(`/bill-review`)과 역량강화실(`/coaching` 선례대조)이 읽는 과거 검토보고서를 두는 곳이다. 배포본에는 선례 파일이 들어 있지 않다. 쓰는 기관이 직접 모아 넣는다. 선례가 없으면 법안검토팀은 선례 없이 쓰고, 역량강화실의 선례대조·훈련은 같은 유형의 승인 결과물을 대신 쓰며 둘 다 없으면 멈춘다(`.claude/skills/coaching/SKILL.md`).

## 넣는 법
1. 의안정보시스템 등 공식 출처에서 검토보고서 원본(PDF·HWP)을 받는다.
2. 원본은 그대로 두고 kordoc으로 같은 이름의 `.md` 사본을 만든다. kordoc이 없으면 PDF를 `pdf` 스킬로 읽어 `.md`로 저장한다.
3. 잘 쓴 보고서는 `.md` 사본 이름 앞에 `모범_`을 붙인다. 에이전트가 먼저 본다.
4. 동기화하지 않을 선례는 파일 이름 앞에 `비공개_`를 붙인다(`.gitignore`).
5. 이 README의 '목록'에 한 줄씩 적는다.

이름 규칙: `대수_위원회_의안번호_약칭[_일부개정]_검토보고_표지연월`. 일부개정안만 `_일부개정`을 붙이고, 병합 건은 의안번호 뒤에 `외N`을 붙인다. `.md` 사본만 이름 앞에 `모범_`이 붙는다.

| 확장자 | 무엇 | 쓰는 곳 |
|---|---|---|
| `.pdf` | 원본 | 쪽·그림·표 배치 확인 |
| `.hwp` | 원본(한글) | 서식 참고 |
| `.md` | kordoc 사본 | Claude가 읽는 용. 첫머리에 출처·변환 정보를 적는다. 그림은 `〔그림: PDF 원본 참조〕`로 표시 |

대비표 밑줄 일부가 사본에서 빠질 수 있으니 표기를 따질 때는 PDF를 본다.

## 고르는 법
- **유형별 3~5건부터**: 제정안, 일부개정안, 여러 법률안을 병합한 건을 고루 넣는다. 전부개정안이 있으면 먼저 넣는다.
- **같은 위원회·같은 시기의 보고서를 묶으면** 문체와 목차가 고르게 맞는다.
- **짜임을 다 갖춘 것부터**: 총괄적 검토와 쟁점별(또는 장별) 검토를 모두 갖춘 보고서가 짜임을 배우기 좋다.
- 처리 결과(가결·폐기 등)는 쓰기 전에 의안 화면에서 다시 확인한다.

## 짜임 예시 (일반)
실제 보고서를 가리키지 않는 일반적인 짜임이다. 선례를 고를 때 유형이 고루 들어갔는지 보는 데 쓴다.

| 구분 | 분량(대략) | 흔한 짜임 |
|---|---|---|
| 일부개정 | 20~50쪽 | 개정 취지 → 쟁점별 검토(현황·개정안·검토·소결) → 참고자료 |
| 일부개정, 여러 건 병합 | 50쪽 넘음 | 법률안별 주요내용 비교 → 쟁점별 검토 → 부칙 검토 |
| 제정 | 50쪽 넘음 | 총괄적 검토(입법 필요성, 관계 부처·단체 의견) → 장별 또는 쟁점별 검토 → 부칙 검토 |
| 제정, 여러 건 병합 | 50쪽 넘음 | 총괄적 검토 → 법률안별 비교 → 쟁점별 검토 |

- 이 폴더의 법률안으로 검토 연습을 할 때는 여기 보고서가 정답지다. 초안을 쓰기 전에는 열지 않는다(검토보고서 플러그인 `bill-sources` 가림 조건).
