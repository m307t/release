# 법제업무팀 — AI 에이전트 팀 (배포본 vanilla)

법제업무를 돕는 AI 에이전트 팀을 3층 건물 구조로 꾸린 저장소입니다. 이 폴더를 자기 비공개 저장소로 옮겨 열면 어느 PC에서든 같은 팀이 일합니다.

> **목적과 최종 책임** — 이 에이전트 팀은 법제업무, 검토보고서 작성 업무, 예결산 검토 업무를 보조하고 그를 위한 일정관리와 자료조사를 하는 도구이며, 법률 자문이나 기관의 공식 의견이 아닙니다.
> 사용자와 함께 시행착오를 겪으며 성장하도록 설계했기 때문에, 배포 시점에는 미숙할 수 있습니다. 처음 쓰는 동안에는 결과물을 더 꼼꼼히 검수해 주세요.
> 결과물은 모두 초안입니다. 사람이 밖으로 내거나 최종 문서로 쓰는 것은 최종 검수자가 원문과 대조해 승인한 것뿐이고, 내용과 쓰임에 대한 판단과 책임은 승인한 사람과 그 소속 기관에 있습니다.
> 생성형 AI는 틀리거나 없는 출처를 만들 수 있고, 검증 에이전트의 '통과'는 사람 검수를 대신하지 않습니다.

## 처음 쓰는 PC
1. 설치: Git(Windows는 Git for Windows), Claude Code 또는 Claude 데스크톱 앱
2. Git 사용자 등록 (PC마다 한 번):
   ```bash
   git config --global user.name "이름"
   git config --global user.email "메일주소"
   git config --global core.quotepath false   # show Korean file names as-is
   ```
3. 내 저장소 만들기 (처음 한 번): GitHub에서 **Private** 저장소를 새로 만들고(README 없이), 이 `vanilla` 폴더의 내용을 그 저장소 맨 위에 올립니다. Windows는 Git Bash에서 같은 명령을 씁니다.
   ```bash
   git clone https://github.com/<배포자>/release.git
   mkdir 법제업무팀 && cp -R release/vanilla/. 법제업무팀/
   cd 법제업무팀
   git init -b main
   git add . && git commit -m "법제업무팀 배포본으로 시작"
   git remote add origin https://github.com/<내 계정>/<내 저장소>.git
   git push -u origin main
   ```
   `<배포자>/release` 자리에는 이 배포본을 받은 배포 저장소의 주소를 넣습니다. 둘째 PC부터는 `git clone https://github.com/<내 계정>/<내 저장소>.git 법제업무팀`으로 받습니다.
   - 배포 저장소 안의 `release/vanilla` 폴더에서는 Claude를 열거나 동기화를 돌리지 않습니다. 동기화 스크립트는 폴더가 git 저장소의 맨 위가 아니면 멈춥니다.
4. 도구 설치 (PC마다 한 번): Windows는 `도구\설치키트\install-windows.bat` 더블클릭, macOS·Linux는 `bash 도구/설치키트/install.sh`. kordoc(한글·PDF 문서 도구)과 bill-review 플러그인이 설치됩니다. KISA 범피스는 배포본에 없어 건너뜁니다. 자세한 내용은 `도구/설치키트/README.md`.
5. 열기: `법제업무팀` 폴더에서 `claude`를 실행하거나, 데스크톱 앱에서 이 폴더를 엽니다.
6. 확인: "구성 점검해 줘"라고 요청해 오류 0건이면 준비가 끝납니다.
7. 우리 기관에 맞추기: "운영 설정의 기관·부서를 ○○로 바꿔 줘"처럼 요청해 `CLAUDE.md` 운영 설정을 채우고, `자료실/선례/<유형>/`에 과거 보고서를 넣습니다.
   - 통합일정표의 건 칸과 캘린더 제목에 의원 이름을 넣는 것은 배포본의 기본 형식입니다(동기화되고 Google Calendar로도 갑니다). 기관 보안 지침에 맞는지 처음에 확인하고, 바꾸려면 "통합일정표 건 칸에서 이름을 빼 줘"처럼 요청합니다(`상황실/통합일정표.md` 머리).
   - 배포본의 선례 폴더는 비어 있습니다. 그 유형의 선례도 승인한 결과물도 없으면 `/coaching` 선례대조·훈련은 맡기지 않고 멈춰, 선례 넣는 법(`자료실/선례/법안검토/README.md`)을 알려 드립니다.
8. 실습: `튜토리얼.md`를 따라 한 건을 끝까지 돌려 봅니다.

## 매일 동기화
- Windows: `동기화.cmd` 더블클릭
- macOS·Linux: `./동기화.sh`
- 작업 시작 전과 끝난 뒤 한 번씩 실행합니다. 올릴 변경 목록을 먼저 보여 주고, `y`를 눌러야 올립니다. Claude가 대신 돌릴 때는 목록을 먼저 보여 주고 승인을 받습니다.
- 순서: 내 변경 커밋 → 다른 PC 변경 받기 → 충돌 표지(`<<<<<<<`) 검사 → 올리기. 충돌이 나면 아무것도 올리지 않고 멈춥니다. 내 변경은 그 PC에 커밋으로 남습니다.
- 오류노트·훈련기록·변경이력처럼 줄을 더하기만 하는 표는 두 PC가 동시에 줄을 더해도 자동으로 합쳐집니다(`.gitattributes`). 이 표들의 머리(적는 법)나 이미 있는 줄을 고치거나 지울 때는 고치기 전과 후에 바로 동기화합니다. 그 밖의 파일은 두 PC에서 동시에 고치지 않습니다.
- 동기화가 멈추면 Claude에게 "동기화 충돌 해결해 줘"라고 요청합니다.

## 무엇이 동기화되나
| 동기화됨 | 그 PC에만 남음 (`.gitignore`) |

| `자료실/` 규칙·서식·교본·선례 | `산출물/` 건 폴더 |
| `라운지/` 오류노트(익명)·훈련기록·개선안, `라운지/훈련/`의 체크리스트 갱신안 | `발송실/` 승인본·.ics 파일 |
| `상황실/통합일정표.md` (확정 일정은 Google Calendar로도), `상황실/현안목록.md`(공개 키워드만), `상황실/대시보드.html`(화면만) | `상황실/브리핑/` (뉴스 브리핑 포함), 대시보드 데이터 파일 |
| | `라운지/훈련/`의 위임지시·훈련 문제·정답 |
| | 검토보고서 플러그인의 작업·입력 폴더(`_workspace/`, `입력/`), 인증키 파일 `.env` |
| | 직접 넣은 KISA 범피스 .exe(`도구/설치키트/payload/windows/`) |

- 전체 목록과 빼는 까닭은 `.gitignore`에 있습니다.
- 내 저장소는 **Private**로 둡니다. 쓰다 보면 선례·오류노트·일정이 쌓이므로 Public으로 바꾸지 마세요.
- 비공개 선례는 파일명 앞에 `비공개_`를 붙이면 동기화에서 빠집니다.
- 산출물도 동기화하려면 `.gitignore`에서 `산출물/**` 줄을 지웁니다. 기관 보안 지침을 먼저 확인하세요. 그러면 건 폴더의 `_진행.md`(익명 ID와 건의 대응)도 올라가 오류노트의 익명이 풀립니다.

## PC마다 확인할 것
- **법령 MCP**: 국가법령정보 MCP는 이 배포본에 들어 있지 않아 직접 연결합니다. 검토보고서 플러그인이 권하는 것은 제3자 오픈소스 korean-law-mcp(https://github.com/chrisryugj/korean-law-mcp, npm `korean-law-mcp`, MIT)입니다.
  - 인증키: 법제처 국가법령정보 공동활용(open.law.go.kr)에서 OC 인증값을 각자 신청합니다. 키는 채팅창에 붙여 넣지 않습니다.
  - Claude Code: `/plugin marketplace add chrisryugj/korean-law-mcp` → `/plugin install korean-law@korean-law-marketplace`. 설치할 때 키를 묻습니다(`도구/설치키트/payload/AI-Assembly/plugins/bill-review/skills/bill-sources/SKILL.md` §1).
  - claude.ai·데스크톱 앱: 그 서버 README의 설치 안내를 따릅니다(claude.ai는 설정 → 커넥터의 커스텀 커넥터). 원격 서버를 쓰면 조회어와 키가 그 서버 운영자에게 갑니다(`면책고지.md` 5).
  - 연결 확인은 Claude Code에서 `/mcp`로 합니다. 연결이 없으면 원장을 만들 수 없습니다. 이때 조문 대조 검사기가 통과를 내더라도, 대비표를 만드는 팀(법제팀, 심사지원팀 소위자료, 법안검토팀 예비 경로)은 검증으로 넘기지 않고 멈춰 사람에게 묻습니다. 검토보고서 플러그인은 산출을 보류합니다. 다른 결과물의 법령 확인은 `[확인 필요]`로 남습니다.
- **설치키트 도구**: kordoc(HWP·PDF 읽기, HWPX 만들기)과 검토보고서 플러그인은 설치키트로 PC마다 설치합니다. 클라우드 세션에는 둘 다 없습니다. 그래서 법안검토팀은 설치키트 PC에서 이어 할지 이 세션에서 예비 경로로 할지 묻고, HWP 입력은 PDF로 바꿔 넣어야 합니다.
- **문서 스킬**: `bill-hwpx-autofill`, `amendment-comparison-table`, `참고조문`, `legislative-review`는 이 배포본에 들어 있지 않고 공개된 표준 스킬도 아닙니다. 쓰는 기관이 따로 마련해 계정에 둔 경우에만 쓰고, 없으면 그 파일(발의서 HWPX, 대비표·참고조문 DOCX 등)은 만들지 않고 마크다운으로 남기며 "도구 미연결로 ○○ 파일 미생성"이라고 알립니다. `xlsx`·`docx`·`pdf` 스킬은 계정에 있으면 씁니다(예결산 재계산 XLSX, PDF 읽기 등).
- **메일**: 메일 커넥터가 없으면 메일을 `안내실/메일/`에 .eml·.txt로 내보내 넣습니다.
- **Google Calendar**: claude.ai 설정 → 커넥터에서 Google Calendar를 연결하면, 상황실이 사람이 확정한 통합일정표 일정을 캘린더에 넣고 고칩니다(`/ops-desk 캘린더`). 일정은 공유하지 않는 전용 캘린더 하나에만 넣으니, Google Calendar에서 미리 만들어 두고 이름을 알려 주세요. 연결하지 않은 PC·세션에서는 `.ics` 파일을 만들어 드리니 Google Calendar 설정 → 가져오기로 넣습니다. 일정 제목 형식은 `상황실/통합일정표.md` 머리에 있습니다.
- **상급자 피드백**: 받은 피드백 파일을 `안내실/피드백/`에 넣고 "상급자 피드백 반영해 줘"라고 요청합니다. 이번 건을 보완하고, 채택한 항목은 검수 체크리스트가 되어 다음 건부터 검증 기준이 됩니다.
- **열린국회정보 API**: 인증키를 쓰려면 PC마다 `.env`에 `ASSEMBLY_KEY=…` 한 줄을 넣습니다(동기화되지 않음). `python3 도구/국회API점검.py`로 접속과 키를 확인합니다. 키 값은 출력하지 않고, 키가 없어도 한 번에 5건까지는 조회됩니다.
- **Python 3.8 이상**: 구성점검, 대시보드 갱신(`도구/대시보드갱신.py`), 메일 사본(`도구/메일사본.py`), 통합일정표 점검·.ics 만들기(`도구/일정내보내기.py`), 열린국회정보 API 점검(`도구/국회API점검.py`), 익명 ID 만들기, 조문 대조 검사기, 검증의 재계산에 씁니다. 없으면 대시보드, 상황실의 파일 메일·캘린더 처리와 조문 대조·예결산 검증을 할 수 없습니다.

## 진행 현황 대시보드
- 진행 현황 대시보드는 건 폴더의 `_진행.md`, 통합일정표, 현안목록, 오류노트·훈련기록, 검수 체크리스트를 한 화면에 모아 보여 줍니다.
- 저장소 폴더에서 `python3 도구/대시보드갱신.py`(Windows는 `py -3 도구\대시보드갱신.py`)를 실행한 뒤 `상황실/대시보드.html`을 더블클릭해 브라우저로 엽니다. Claude에게 "대시보드 갱신해 줘"라고 요청해도 됩니다.
- 화면은 인터넷 연결 없이 열립니다. D-n은 도구를 실행한 날 기준이므로 날이 바뀌면 다시 실행하고 새로 고칩니다.
- 데이터 파일 `상황실/대시보드_데이터.js`(있으면)는 건 내용을 담으므로 동기화하지 않고(`.gitignore`) 게시하지도 않습니다.
- 대시보드는 에이전트 기록을 모아 보여 줄 뿐입니다. 원문 대조와 최종 판단은 최종 검수자가 합니다(면책고지.md).

## 클라우드 세션 (claude.ai/code)
내 저장소를 선택해 세션을 시작하면 브라우저·모바일에서도 같은 팀을 씁니다. 세션 컨테이너는 끝나면 지워집니다. 업무기술서·자료실 변경은 커밋·푸시하고, `산출물/`의 건 폴더는 동기화 대상이 아니므로 이어 하려면 내려받아 두세요. 건은 같은 PC에서 이어 하고, 다른 PC에서 이어 하려면 건 폴더를 통째로 옮깁니다.
- 클라우드 세션에서 올린 변경은 세션 브랜치(`claude/…`, `ccr-…` 등)에만 들어가고 main에는 들어가지 않습니다. 다른 PC에서 받으려면 GitHub에서 그 브랜치를 main에 병합합니다. PR을 만들거나 병합하는 일은 사람이 하거나, 사람이 요청할 때 Claude가 합니다.
- **아침 뉴스 예약(선택)**: 기본으로 꺼져 있습니다. 매일 아침 뉴스 브리핑을 받으려면 `사용설명서.md`의 '아침 뉴스 예약'대로 발사대 세션 「뉴스 발사대」와 claude.ai 예약작업 「오늘의 뉴스」를 만들고, 실행 시각을 상황실 팀 설정의 '뉴스 예약 실행'에 적습니다.
  - 켜면 예약작업이 발사대 세션을 깨웁니다. 발사대는 실행마다 이 저장소를 붙인 새 클라우드 세션 「오늘의 뉴스 M월 D일」을 만들고, 그 세션이 main 최신으로 상황실 뉴스 모드를 무인으로 돌립니다. 실행마다 새 세션이라 한 세션에 대화가 쌓이지 않습니다.
  - 지난 날의 뉴스 세션은 세션 목록에 쌓이니, 필요 없으면 사람이 보관(archive)합니다.
- 클라우드 환경의 네트워크 설정에 따라 국회 의안정보시스템(likms.assembly.go.kr)·국회 입법예고(pal.assembly.go.kr) 같은 사이트가 막힐 수 있습니다. 세션 제목 줄의 환경 메뉴 → 편집 → 네트워크 접근에서 허용 도메인에 넣으면 열립니다(안내: https://code.claude.com/docs/en/cloud-environments#network-access). 막혀 있으면 뉴스 브리핑의 의안 확인이 `[확인 필요]`로 남습니다.
