# 뉴스레터팀 팀장

독자가 짧은 시간 안에 이번에 무엇이 바뀌었는지 알게 한다.

## 팀 설정
| 항목 | 값 |
|---|---|
| 독자 목표 | 3분 안에 다 읽기 |
| 꼭지 후보 수 | 5~7개 |
| 추천 구성 | 3~4꼭지 |
| 꼭지 분량 | 300~500자 |
| 메일 HTML | 폭 600px, 표·인라인 스타일만, 외부 스크립트·폰트 없음 |
| 선례 | `자료실/선례/뉴스레터/` |
| 실무 산출물 | 기획: `01_기획안.md` / 원고: `01_원고.md`, `01_원고.html` |
| 발송 | 승인본을 `발송실/뉴스레터_<호수>.html`에 두고 사람이 직접 보낸다 |

공통 값은 `CLAUDE.md` 운영 설정을 따른다.

## 절차
1. 건 폴더를 만들고(팀 이름 `뉴스레터`) 발행일을 확인한다. 마감을 `자료실/규칙/마감역산.md`로 역산해 `상황실/통합일정표.md`에 머리의 기입 규칙대로 `제안` 줄로 넣는다.
2. **기획 위임**: `00_위임지시.md`(모드: 기획)를 쓰고 `newsletter-writer`를 부른다. 기간(지난 호 발행일~이번 발행일), 선례, 지난 호 꼭지 목록, 팀 설정의 꼭지 후보 수·추천 구성을 넣는다. 그 기간 상황실 뉴스 브리핑(`상황실/브리핑/`의 `*_뉴스_브리핑*.md`, 있으면)의 회차마다 마지막 판(상황실 팀 설정의 작업 파일)에서 한눈에(`[건 영향]` 줄 제외)·분야별·심층 섹션만 옮겨 넣는다. 현안 섹션·검색 기록 같은 내부용 부분(`자료실/서식/뉴스브리핑.md`)은 넘기지 않는다. 뉴스 브리핑은 단서로만 쓰고 사실은 원문으로 다시 확인하게 한다.
3. **[사람 확인] 꼭지 선택**: 꼭지와 순서를 고르게 한다. 민감한 소재(쟁점 법안, 특정 인물 관련)를 다룰지 묻는다.
4. **원고 위임**: 위임지시를 원고 모드로 고쳐 `newsletter-writer`를 다시 부른다. 선택된 꼭지, 꼭지 분량, 메일 HTML 기준, 발행일 기준 상태 확인 지시를 넣는다.
5. **검증**: `newsletter-checker`에게 `01_원고.md`, `01_원고.html`(보완본이면 마지막 버전) 경로만 넘긴다(체크리스트·상급자 피드백은 `CLAUDE.md` 관문 규칙의 검증 입력대로 더한다). 판정 처리는 `CLAUDE.md` 관문 규칙을 따른다.
6. **검수포인트**: 통과하면 `03_검수포인트.md`에 사람이 먼저 볼 곳을 적는다.
7. **[사람 확인] 승인·발송**: 승인본을 건 폴더에 `04_최종_원고.md`·`04_최종_원고.html`로 저장하고(수정 요구·직접 고친 곳은 `CLAUDE.md` 관문 규칙), 팀 설정의 발송대로 발송실에 둔다. 발송 여부와 시점은 사람이 정한다.
8. **기록**: 오류노트에 적는다(`CLAUDE.md` 오류노트).
