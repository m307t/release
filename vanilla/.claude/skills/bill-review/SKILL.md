# 법안검토팀 팀장

위원이 상정 전에 읽고 판단할 검토보고서를 만든다. 실무는 검토보고서 플러그인이 맡고, 이 팀장은 건 폴더·사람 확인·검수포인트·오류노트를 잇는다. **결론의 수위는 사람이 정한다.**

## 팀 설정
| 항목 | 값 |
|---|---|
| 실무 엔진 | 검토보고서 플러그인 `bill-review@ai-assembly` (팀장 스킬 `bill-review:bill-review`) |
| 예비 경로 | 플러그인이 없을 때만: `bill-review-writer` → 조문 대조 → `bill-review-checker` |
| 작업 폴더 | 건 폴더. 플러그인의 `_workspace/`도 건 폴더 안에 만든다 |
| 내 검토 기준 | `자료실/교본/검수체크리스트_법안검토.md`(있으면), `자료실/선례/법안검토/` |
| 쟁점 수위 선택지 | 원안 타당 / 수정 필요 / 신중 검토 |
| 목차 | 플러그인 경로는 플러그인 기준. 예비 경로는 `자료실/서식/검토보고서_목차.md` |
| 조문 대조 | 예비 경로: 단일 건은 `01_초안.md`를 법률안 원문 사본(`--bill`)과 함께 대조한다. 병합 건은 `01_대비표_<의안번호>.md`를 하나씩 그 법률안 원문 사본(`--bill`)과 함께, `01_초안.md`는 `--bill` 없이 인용 조문만 대조한다(`자료실/규칙/조문대조.md`). 플러그인 경로: 플러그인 6단계(조문 대조 검문소)가 돌린다 |
| 배부 기한 | `자료실/규칙/마감역산.md`의 검토보고서 |
| 검수포인트 우선 | 플러그인 최종 보고의 "사람이 판정할 것", 조문 대조의 △, 결론 문장, C등급 이하 근거 |

공통 값은 `CLAUDE.md` 운영 설정을 따른다.

## 절차
1. **접수**: 법률안 원문(PDF·HWP) 또는 의안번호를 확인하고 건 폴더를 만든다(팀 이름 `법안검토`). 원본은 `원자료/`로 옮기고 `.md` 사본을 만든다. 건 폴더·`.md` 사본·`_진행.md`·현안 등록(운영 설정의 현안 등록 대상 팀이면)은 `CLAUDE.md` 건 폴더 표준을 따른다.
2. **의안 정보·기한**: 의안번호, 제안자, 제안일, 회부일, 소관 위원회를 원문에서 확인한다. 상정 예정일이 있으면 배부 기한을 역산해 `상황실/통합일정표.md`에 머리의 기입 규칙대로 `제안` 줄로 넣는다. 병합 대상 법률안이 있는지 사람에게 확인한다.
3. **엔진 확인**: 스킬 목록에 `bill-review:bill-review`가, 에이전트 목록에 `bill-review:bill-designer`(또는 `bill-designer`) 등 플러그인 팀원이 보이면 플러그인 경로(4)로 간다. 보이지 않으면 멈추고 사람에게 고르게 한다.
   - 설치키트를 실행한 PC에서 이어서 한다 (권장)
   - 이 세션에서 예비 경로(5)로 진행한다
4. **플러그인 경로**: Skill 도구로 `bill-review:bill-review`를 불러 그 절차를 따른다. 아래만 바꿔 적용한다.
   - 작업 폴더는 건 폴더의 절대 경로다. `_workspace/`는 `<건 폴더>/_workspace/`에 만든다.
   - 입력 자료는 `<건 폴더>/원자료/`에 있다. `_진행.md`의 '넘겨받은 자료'에 조사노트가 있으면 그 경로도 입력 자료로 함께 주고, `_workspace/00_input/_목록.md`에도 플러그인 형식대로 적는다.
   - 내 검토 기준: 팀장이 검수 체크리스트(팀 설정)의 `사용` 항목만 플러그인의 착안점 형식(`| 착안점 | 점검 질문 | 확인할 자료 | 근거 |`)으로 옮겨 `<건 폴더>/내_검토기준.md`를 만들어 넘긴다. 체크리스트가 없으면 만들지 않는다. 선례 폴더는 목차·문체 참고 자료로 따로 준다.
   - 관문② 검수관 프롬프트에 검수 체크리스트 경로를 더하고, `사용` 항목마다 지킴·어김·해당 없음을 판정서 '체크리스트 점검' 절에 적게 한다. 어긴 것은 [필수]다.
   - 작업 폴더 `CLAUDE.md` 안내는 건너뛴다. 이 저장소의 `CLAUDE.md`가 업무지침이다.
   - 쟁점 승인 관문에서 쟁점별 수위(팀 설정의 선택지)를 함께 묻는다.
   - 플러그인 팀원을 부를 때 법령 도구 이름이 환경마다 다르다는 점(`CLAUDE.md` 서버실)을 알린다.
   - 플러그인의 관문①, 쟁점 승인, 조문 대조 검문소, 관문②는 생략하지 않는다.
   - 상급자 피드백이 오면(`CLAUDE.md` 상급자 피드백) 관문② [필수]를 고칠 때와 같이 돌린다.
     - 항목 파일을 `_workspace/00_요청.md` ⑤에 덧붙인다. 새 근거가 필요한 항목은 조사관에게 그 항목만 조사시켜 근거장부에 더한다.
     - 집필가에게 항목 파일을 주고 고치게 한 뒤, 조문·대비표가 바뀌었으면 검문소를 다시 돌린다. 고친 내역은 `_workspace/04_피드백반영.md`(F번호 | 고친 곳 | 고친 내용)에 따로 쓰게 한다. `04_검토보고서.md`는 그대로 최종본으로 복사되므로 맨 위에 보완 내역 표를 달지 않는다.
     - 검수관에게 원문 사본·항목 파일·`_workspace/04_피드백반영.md` 경로와 `자료실/규칙/검증공통.md`(피드백 반영 점검 규칙)를 주고, 바뀐 단락을 관문② 여섯 축으로 다시 판정받는다. 판정서에는 피드백 반영 점검 표(F번호 | 반영 위치 | 반영됨 / 안 됨 / 제외 / 판단 필요)를 붙이게 한다. '반영'으로 정한 항목이 반영되지 않았으면 [필수], '제외' 항목은 판정하지 않고, 항목 누락·법령 충돌은 〔판단 필요〕로 적게 한다.
     - 그 판정서는 `_workspace/05_검수판정.md`에 「피드백 재판정」 제목으로 덧붙인다. 이 재판정의 [필수]는 이 팀장 스킬 8(기록)의 '발견자: 검증' 집계에서 뺀다.
5. **예비 경로**: 플러그인이 없고 사람이 이 경로를 고른 때만 쓴다.
   1. 쟁점 도출: 개정 조문별 쟁점 후보를 `01_쟁점목록.md`에 쓴다. 입법례·통계가 필요하면 `/research`를 먼저 부르고, 조사팀이 넘긴 통과본 경로를 쓴다.
   2. **[사람 확인] 쟁점별 수위**: 팀 설정의 선택지로 고르게 한다. 협의 경과(부처 의견 등)를 넣을지도 묻는다.
   3. 위임: `자료실/서식/위임지시.md` 형식으로 `00_위임지시.md`를 쓰고 `bill-review-writer`를 부른다.
   4. 조문 대조: 팀 설정의 조문 대조 대상을 `자료실/규칙/조문대조.md` 절차로 대조해 `01c_조문대조.md`에 이어 붙인다. 불통과면 검증으로 넘기지 않고 고친다.
   5. 검증: `bill-review-checker`에게 `01_초안.md`, `01_조문검토매핑.md`, (병합 건이면) `01_대비표_*`(모두 보완본이면 마지막 버전), `원자료/`, (조사를 거쳤으면) 통과본 조사노트와 `조사/출처사본/` 경로만 넘긴다(조문 대조 결과·체크리스트·상급자 피드백은 `CLAUDE.md` 관문 규칙의 검증 입력대로 더한다). 판정 처리는 `CLAUDE.md` 관문 규칙을 따른다.
6. **검수포인트**: `03_검수포인트.md`에 팀 설정의 우선 항목과 오류노트상 자주 틀린 유형에서 고른다.
7. **승인 후**: 사람이 결론을 정하고 승인하면 최종본을 저장한다(수정 요구·직접 고친 곳은 `CLAUDE.md` 관문 규칙). 플러그인 경로는 `_workspace/04_검토보고서.md`(변환했으면 `06_검토보고서.hwpx`도)를 `04_최종_검토보고서.md`(`.hwpx`)로 복사한다. 예비 경로는 `01_초안`의 마지막 버전을 같은 이름으로 저장한다(필요하면 docx 스킬로 DOCX).
8. **기록**: 오류노트에 적는다(`CLAUDE.md` 오류노트). 플러그인 경로는 `02_설계판정.md`·`05_검수판정.md`의 [필수]와 `04c_조문대조.md`의 ✕를 "발견자: 검증"으로 적는다. 운영 설정의 현안 등록 대상 팀이면 `상황실/현안목록.md` 머리의 적는 법대로 상태를 종료로 바꾼다.

## 하지 않는 것
- 쟁점의 결론을 사람 확인 없이 정하지 않는다.
- 제안이유 및 주요내용을 요약·윤문하지 않는다(원문 그대로).
- 플러그인이 없다고 말없이 예비 경로로 넘어가지 않는다.
