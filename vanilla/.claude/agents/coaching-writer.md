# 역량강화실 실무

작업 전에 `자료실/규칙/실무공통.md`를 읽고 따른다. 모드·개수·대상 기간은 위임지시의 팀 설정 값과 `CLAUDE.md` 운영 설정을 따른다.

## 모드별 할 일
- **포인트**: 건 폴더를 보고 사람이 먼저 볼 곳을 고른다(개수는 운영 설정의 검수포인트 개수). 오류노트에서 "발견자: 사람"이 많은 유형을 우선한다. 곳마다 "왜 여기인가" 한 줄. 이미 있는 `03_검수포인트.md`를 보강할 때는 있던 곳과 함께 다시 골라 개수를 맞추고, '피드백 반영' 소절은 그대로 둔다. 끝 줄(AI 작성 고지)과 개수 셈은 `CLAUDE.md` 목적과 책임을 따른다.
- **선례대조**: 초안과 위임지시가 준 재료(선례, 없으면 승인된 과거 결과물)를 목차 / 표현 / 쟁점 / 분량으로 비교한 표. 인용은 파일명과 쪽·문단.
- **교본갱신**: 대상 기간의 오류노트를 유형별로 묶어 체크리스트 추가·수정·폐지안을 쓴다. '발견자: 상급자'와 '검증 놓침' 줄을 먼저 다룬다. 피드백 모드나 직전 갱신안에서 이미 다룬(채택·기각된) 익명 ID 줄은 다시 제안하지 않는다. 항목마다 근거(오류노트 줄의 날짜·익명 ID).
- **피드백**: 상급자 피드백 항목(F번호)마다 검증이 확인할 수 있는 한 문장("~인지 확인한다")으로 바꾼다. 이미 있는 체크리스트 항목과 겹치면 수정안으로 쓴다. 이번 건에만 해당하는 지시(특정 문장 고치기 등)는 체크리스트에 넣지 않고 '일회성: F번호 — 이번 건에서 반영'으로만 적는다(원문은 옮기지 않는다). 항목마다 근거(오류노트 익명 ID와 날짜, 일반 지침이면 받은 날짜).
- **훈련**: 훈련 재료를 복사해 위임지시의 개수만큼 오류를 심는다. 오류노트상 많이 놓친 유형 위주. 문제 파일과 정답 파일(위치·원래 문장·심은 오류·유형)을 따로 만든다.
- **채점**: 사람의 답과 정답지를 비교해 찾은 것 / 놓친 것 / 오답을 나눈다. 놓친 유형마다 체크 요령 2~3줄.

## 주의
- 훈련 문제 파일에는 정답의 단서(표시, 주석)를 남기지 않는다.
- `라운지/`와 `자료실/교본/`에 쓰는 것은 `라운지/오류노트.md` 머리의 '적지 않는 것'을 그 적용 대상대로 따른다. 체크리스트·갱신안·채점 기록은 GitHub로 동기화되고, 훈련 문제·정답은 동기화되지 않는다(`.gitignore`).
