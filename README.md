# 법제업무팀 — AI 에이전트 팀 (배포본 vanilla)

법제업무를 돕는 AI 에이전트 팀을 3층 건물 구조로 꾸린 저장소입니다. 이 저장소를 받아 자기 GitHub 비공개 저장소로 만들어 열면 어느 PC에서든 같은 팀이 일합니다.

> **목적과 최종 책임** — 이 에이전트 팀은 법제업무, 검토보고서 작성 업무, 예결산 검토 업무를 보조하고 그를 위한 일정관리와 자료조사를 하는 도구이며, 법률 자문이나 기관의 공식 의견이 아닙니다.
> 사용자와 함께 시행착오를 겪으며 성장하도록 설계했기 때문에, 배포 시점에는 미숙할 수 있습니다. 처음 쓰는 동안에는 결과물을 더 꼼꼼히 검수해 주세요.
> 결과물은 모두 초안입니다. 사람이 밖으로 내거나 최종 문서로 쓰는 것은 최종 검수자가 원문과 대조해 승인한 것뿐이고, 내용과 쓰임에 대한 판단과 책임은 승인한 사람과 그 소속 기관에 있습니다.
> 생성형 AI는 틀리거나 없는 출처를 만들 수 있고, 검증 에이전트의 '통과'는 사람 검수를 대신하지 않습니다.
> 전체 문구: [면책고지.md](면책고지.md) · 제3자 구성요소와 라이선스: [제3자고지.md](제3자고지.md)

만든 사람: 백현민 · 문의: bhm0307@naver.com

> **공개 배포 저장소에서 받아 내 저장소로 씁니다** — 이 배포본은 누구나 받을 수 있는 공개 저장소(배포 저장소)에 있습니다. 받은 사람은 각자 GitHub에 **Private** 저장소를 만들어 옮겨 쓰고, **Fork하지 않습니다**(공개 저장소의 포크는 비공개로 바꿀 수 없습니다).
> 지금 판, 배포 저장소 주소, 판별로 바뀐 것은 [배포판.md](배포판.md)에 있습니다. 받는 법은 [처음 쓰는 PC](#처음-쓰는-pc), 새 판을 받는 법은 [새 판 받기](#새-판-받기), 이용 조건은 [배포 저장소와 이용 조건](#배포-저장소와-이용-조건)에 있습니다.

## 처음 쓰는 PC
순서는 내 Private 저장소 만들기 → Claude로 열어 구성 점검 → 튜토리얼로 가상 예제 한 건 → 실제 업무입니다. 먼저 써 보기만 하려면 내 저장소 없이 8의 연습 폴더에서 튜토리얼부터 해도 됩니다.

1. 설치: Git(Windows는 Git for Windows), Claude Code 또는 Claude 데스크톱 앱, Python 3.8 이상(아래 'PC마다 확인할 것'). 내 저장소를 둘 GitHub 계정도 있어야 합니다.
2. Git 사용자 등록 (PC마다 한 번). Windows는 Git Bash나 PowerShell에서 실행합니다(명령 프롬프트는 `#` 설명 줄을 읽지 못합니다):
   ```bash
   git config --global user.name "이름"
   git config --global user.email "메일주소"
   # show Korean file names as-is
   git config --global core.quotepath false
   ```
3. 내 저장소 만들기 (처음 한 번): 배포 저장소는 공개 저장소라 그대로 쓰지 않고, 내 GitHub 계정에 **Private** 저장소를 만들어 옮깁니다. 아래 세 방법 가운데 하나로 합니다. 저장소 이름은 영문을 권합니다(예: `legal-office`).
   - **먼저 GitHub 로그인**: 내 저장소는 비공개라 PC에서 받고 올릴 때 로그인이 필요합니다. Windows는 Git for Windows가 띄우는 로그인 창에서 로그인합니다. macOS·Linux는 GitHub CLI의 `gh auth login`이나 Git Credential Manager로 먼저 로그인해 둡니다. 비밀번호를 묻는 칸에는 GitHub 계정 비밀번호가 아니라 토큰(personal access token)을 넣습니다.
   - **방법 1. 웹에서 가져오기 (권장)**: GitHub 오른쪽 위 `+` → **Import repository**(https://github.com/new/import)를 엽니다. 원본 주소에 `https://github.com/m307t/release`를 넣고, 내 계정과 저장소 이름을 정한 뒤 **Private**을 골라 **Begin import**를 누릅니다. 가져오기가 끝나면 PC에서 받습니다.
     ```bash
     git clone https://github.com/<내 계정>/<내 저장소>.git 법제업무팀
     cd 법제업무팀
     ```
   - **방법 2. 터미널에서**: GitHub에서 빈 **Private** 저장소를 만듭니다(README·.gitignore·라이선스를 더하지 않습니다). 그다음 배포 저장소를 받아 연결을 내 저장소로 바꾸고 올립니다. Windows는 Git Bash나 PowerShell에서 같은 명령을 씁니다.
     ```bash
     git clone https://github.com/m307t/release.git 법제업무팀
     cd 법제업무팀
     git remote set-url origin https://github.com/<내 계정>/<내 저장소>.git
     git push -u origin main
     ```
   - **방법 3. ZIP으로 (기록 없이 시작)**: 배포 저장소의 **Code** → **Download ZIP**으로 받아 압축을 풀고, 나온 폴더(`release-main`)의 이름을 `법제업무팀`으로 바꿉니다. 내용만 다른 폴더로 옮길 때는 이름이 점(.)으로 시작하는 숨김 항목(`.claude` 폴더, `.gitignore`, `.gitattributes`)까지 빠짐없이 옮깁니다. 방법 2처럼 빈 Private 저장소를 만든 뒤, 그 폴더에서 연결하고 첫 동기화로 올립니다. 올릴 목록을 확인하고 `y`를 누릅니다.
     ```bash
     cd 법제업무팀
     git init -b main
     git remote add origin https://github.com/<내 계정>/<내 저장소>.git
     ./동기화.sh   # on Windows, double-click 동기화.cmd instead
     ```
     올릴 목록에 `.env`나 `산출물/`이 보이면 `y`를 누르지 않습니다. 숨김 파일 `.gitignore`가 빠진 것이고, 구성점검도 이를 오류로 알립니다. 받은 ZIP에서 숨김 항목을 다시 옮긴 뒤 동기화합니다.
   - 방법 1·2는 배포본과 git 기록이 이어져, 새 판을 보통의 병합으로 받습니다. 방법 3(과 GitHub 템플릿 기능으로 만든 저장소)은 기록이 이어지지 않아, 처음 새 판을 받을 때 업데이트가 처음 받은 판을 찾아 기준으로 잇습니다([새 판 받기](#새-판-받기)).
   - **하지 말 것**: 배포 저장소에서 **Fork**를 누르지 않습니다. 공개 저장소의 포크는 공개로만 만들어지고 비공개로 바꿀 수 없어, 쌓인 선례·오류노트·일정이 공개됩니다. 내 저장소를 Public으로 만들지도 않습니다. 배포 저장소의 이슈·토론·PR에 건 내용을 올리지 않는 것도 같은 까닭입니다([배포 저장소와 이용 조건](#배포-저장소와-이용-조건)).
   - 둘째 PC부터는 `git clone https://github.com/<내 계정>/<내 저장소>.git 법제업무팀`으로 받습니다. 비공개 저장소라 GitHub 로그인 창이 뜨면 그 저장소에 접근할 수 있는 계정으로 로그인합니다.
4. 도구 설치 (PC마다 한 번): `법제업무팀` 폴더에서 Windows는 `도구\설치키트\install-windows.bat` 더블클릭, macOS·Linux는 `bash 도구/설치키트/install.sh`를 실행합니다. kordoc(한글·PDF 문서 도구)과 bill-review 플러그인이 설치됩니다. KISA 범피스는 배포본에 없어 건너뜁니다. 자세한 내용은 `도구/설치키트/README.md`.
5. 열기: 내 저장소를 받은 `법제업무팀` 폴더에서 `claude`를 실행하거나, 데스크톱 앱에서 이 폴더를 엽니다.
6. 확인: GitHub의 내 저장소 이름 옆에 **Private**(자물쇠) 표시가 있는지, 폴더에서 `git remote -v`를 실행하면 내 저장소 주소가 나오는지 봅니다. 그다음 "구성 점검해 줘"라고 요청해 오류 0건이면 준비가 끝납니다.
7. 우리 기관에 맞추기: "운영 설정의 기관·부서를 ○○로 바꿔 줘"처럼 요청해 `CLAUDE.md` 운영 설정을 채우고, `자료실/선례/<유형>/`에 과거 보고서를 넣습니다.
   - 통합일정표의 건 칸과 캘린더 제목에 의원 이름을 넣는 것은 배포본의 기본 형식입니다(동기화되고 Google Calendar로도 갑니다). 기관 보안 지침에 맞는지 처음에 확인하고, 바꾸려면 "통합일정표 건 칸에서 이름을 빼 줘"처럼 요청합니다(`상황실/통합일정표.md` 머리).
   - 배포본의 선례 폴더는 비어 있습니다. 그 유형의 선례도 승인한 결과물도 없으면 `/coaching` 선례대조·훈련은 맡기지 않고 멈춰, 선례 넣는 법(`자료실/선례/법안검토/README.md`)을 알려 드립니다.
8. 실습: `튜토리얼.md`를 따라 한 건을 끝까지 돌려 봅니다. 실제 저장소가 아닌 **연습 폴더**에서 하기를 권합니다. 연습 폴더는 공개 배포 저장소를 그대로 받은 복제본이라 내 저장소가 없어도 됩니다. 아래 명령은 내 저장소 폴더(`법제업무팀`) 밖, 같은 상위 폴더에서 실행합니다(Windows는 Git Bash나 PowerShell).
   ```bash
   # if you are inside 법제업무팀, go one level up first
   cd ..
   git clone https://github.com/m307t/release.git 법제업무팀_연습
   git -C 법제업무팀_연습 remote remove origin
   ```
   - 실제 저장소 폴더 안에 받지 않습니다. 연결을 끊어 두면 올릴 곳이 없어, 동기화를 잘못 돌려도 커밋하기 전에 멈춥니다(끊지 않아도 공개 배포 저장소로는 동기화가 멈춥니다). 연습 폴더에서는 동기화하지 않고(새 판 받기도 `--check` 확인만 됩니다), 원격을 다시 붙이거나 다른 곳으로 올려 달라고 하지 않습니다.
   - 연습이 끝나면 폴더째 지웁니다. Google Calendar에 가져온 연습 일정은 캘린더에서 직접 지웁니다.
   - 내 저장소나 버릴 클라우드 세션에서 연습하는 법과 정리 목록은 튜토리얼의 [0. 시작 전에](튜토리얼.md#0-시작-전에)와 [10. 마치며](튜토리얼.md#10-마치며)에 있습니다.

## 매일 동기화
- Windows: `동기화.cmd` 더블클릭
- macOS·Linux: `./동기화.sh`
- 작업 시작 전과 끝난 뒤 한 번씩 실행합니다. 고친 파일이 있으면 올릴 변경 목록을, 고친 파일 없이 올릴 커밋만 있으면(새 판을 받은 직후 등) 올릴 커밋 목록을 먼저 보여 주고, `y`를 눌러야 올립니다. 변경 목록에서 이미 `y`를 눌렀으면 커밋 목록에서 다시 묻지 않습니다. Claude가 대신 돌릴 때는 목록을 먼저 보여 주고 승인을 받은 뒤 `--yes`로 돌립니다.
- 순서: 내 변경 커밋 → 다른 PC 변경 받기 → 충돌 표지(`<<<<<<<`) 검사 → 올리기. 충돌이 나면 아무것도 올리지 않고 멈춥니다. 내 변경은 그 PC에 커밋으로 남습니다. 받기는 보통 다른 PC의 변경 위에 내 커밋을 다시 얹고(`git pull --rebase`), 아직 올리지 않은 병합 커밋(받은 새 판)이 있으면 대신 병합으로 받아(`git pull --no-rebase`) 새 판의 병합 기록을 그대로 둡니다.
- 폴더가 공개 배포 저장소에 연결되어 있으면(배포 저장소를 그대로 받은 폴더, https·ssh 주소 모두) 아무것도 올리거나 받지 않고 멈춥니다. [처음 쓰는 PC](#처음-쓰는-pc) 3대로 내 저장소에 연결한 폴더에서 돌립니다.
- 올릴 원격(origin)이 없는 폴더(연습 폴더, ZIP으로 시작해 연결을 빠뜨린 폴더)도 커밋하기 전에 "이 폴더에는 올릴 곳(원격 origin)이 없어 동기화하지 않습니다"(Windows는 `Sync stopped: this folder has no remote to upload to`)로 멈추고, 아무것도 커밋하지 않습니다.
- 올리는 곳이 GitHub의 공개(Public) 저장소(배포 저장소의 포크, Public으로 바꾼 저장소)여도 멈춥니다. 로그인 없이 GitHub에 그 저장소가 공개인지 물어 확인하는 최선의 보호일 뿐이라, 인터넷이 없거나 답을 받지 못하면 막지 못하고 그대로 진행합니다. 내 저장소가 Private인지는 [처음 쓰는 PC](#처음-쓰는-pc) 6대로 직접 확인합니다.
- 오류노트·훈련기록·변경이력처럼 줄을 더하기만 하는 표는 두 PC가 동시에 줄을 더해도 자동으로 합쳐집니다(`.gitattributes`). 이 표들의 머리(적는 법)나 이미 있는 줄을 고치거나 지울 때는 고치기 전과 후에 바로 동기화합니다. 그 밖의 파일은 두 PC에서 동시에 고치지 않습니다.
- 동기화가 멈추면 Claude에게 "동기화 충돌 해결해 줘"라고 요청합니다.

## 새 판 받기
배포자가 새 판을 내면 배포 저장소의 `배포판.md`에 판과 바뀐 것이 한 줄 더해집니다. 새 판 받기는 그 판을 이 저장소에 git으로 합칩니다. 배포본만 바꾼 파일은 새 판으로 바뀌고, 이 저장소에서만 고친 파일은 그대로 남고, 양쪽에서 고친 파일은 git이 합칩니다.

먼저 동기화합니다. 고친 채 올리지 않은 파일이나 아직 받지 않은 다른 PC의 변경이 있으면 새 판 받기가 멈춥니다.
- Windows: `업데이트.cmd` 더블클릭
- macOS·Linux: `./업데이트.sh` (Windows의 Git Bash 창에서는 받을지 물어볼 수 없어 멈추므로, Windows는 `업데이트.cmd`를 씁니다)
- 들어올 것을 먼저 보여 주고, `y`를 눌러야 받습니다. 보기만 하려면 `./업데이트.sh --check`(Windows는 `py -3 도구/업데이트.py --check`)로 실행합니다. 아무것도 바꾸지 않습니다.
- Claude에게 "새 판 나왔는지 확인해 줘", "새 판 받아 줘"라고 요청해도 됩니다. Claude는 먼저 `python3 도구/업데이트.py --check`(Windows는 `py -3 도구/업데이트.py --check`)의 결과를 보여 드리고, 승인을 받은 뒤 `--yes`를 붙여 받습니다.
- 보여 주는 것: 지금 판과 배포 저장소의 최신판, 새로 들어오는 판(`배포판.md`의 판별 바뀐 것), 배포본이 바꾼 파일, 이 저장소에서도 고친 파일. 받을 것이 없으면 '이미 최신판입니다'라고 나옵니다.
- 받는 곳: `배포판.md`의 배포 저장소에서 main을 받아 `refs/remotes/release/main`에 둡니다. 원격을 더하지 않고, 배포 저장소로는 아무것도 올리지 않습니다.
- 받은 뒤: 구성점검 결과를 보여 줍니다. 내 GitHub 저장소에는 아직 올라가지 않았으므로 곧바로 동기화로 올립니다. 새 판은 한 PC에서 받아 동기화하고, 다른 PC는 동기화로 받습니다.
- 설치키트가 바뀐 판: 확인할 때와 받은 뒤 "참고: 설치키트(도구/설치키트/)가 바뀌었습니다"가 나옵니다. 그러면 PC마다 설치키트를 다시 실행합니다([처음 쓰는 PC](#처음-쓰는-pc) 4). 다른 PC는 동기화로 받은 뒤 실행합니다.

멈출 때는 아무것도 바꾸지 않습니다.

| 멈추는 까닭 | 할 일 |
|---|---|
| 고친 채 올리지 않은 파일이 있음 | 먼저 동기화하고 다시 받습니다 |
| 다른 PC에서 올린 변경을 아직 받지 않음 | 먼저 동기화하고 다시 받습니다 |
| 연습 폴더(공개 배포 저장소에 연결되었거나 원격이 없음) | 확인(`--check`)만 됩니다. 실제 업무는 [처음 쓰는 PC](#처음-쓰는-pc) 3으로 만든 내 저장소에서 합니다 |
| 내 저장소의 최신 상태를 확인하지 못함 | 인터넷 연결과 GitHub 로그인을 확인합니다. 사람이 직접 동기화해 되는지 본 뒤 다시 받습니다(Claude가 돌릴 때는 로그인 창이 뜨지 않습니다) |
| 배포 저장소에서 받지 못함 | 인터넷 연결과 `배포판.md`의 배포 저장소 주소를 확인합니다. 클라우드 세션이면 PC에서 합니다 |
| 얕은 복제(shallow clone)라 배포본과 이어진 곳을 찾지 못함 | PC에서 전체를 받은 내 저장소에서 하거나, `git fetch --unshallow`로 기록을 모두 받은 뒤 다시 합니다 |
| 아직 첫 커밋이 없음(ZIP으로 시작해 첫 동기화 전) | [처음 쓰는 PC](#처음-쓰는-pc) 3의 방법 3대로 첫 동기화를 한 뒤 다시 받습니다 |
| 끝나지 않은 병합·리베이스가 있음 | 메시지를 Claude에게 보여 줍니다 |
| Git 사용자 등록이 없음 | [처음 쓰는 PC](#처음-쓰는-pc) 2를 합니다 |
| 이 저장소와 배포본이 같은 줄을 고쳐 충돌함 | Claude에게 "업데이트 충돌 해결해 줘"라고 요청합니다 |

- 충돌: 배포본이 바꾼 파일을 이 사무실에서도 고쳤으면 git이 합칩니다. 같은 줄을 양쪽에서 고쳤을 때만 멈추고 충돌한 파일을 알려 줍니다. Claude가 풀 때는 `--yes --leave-conflicts`로 병합을 열어 두고 충돌한 곳을 풉니다.
- 충돌을 줄이려면 우리 기관 형식은 업무기술서 문장을 고치기보다 선례(`자료실/선례/<유형>/`)로 맞춥니다. `수정안내.md`의 원칙과 같은 방향입니다.
- ZIP·템플릿으로 시작한 저장소: 배포본과 git 기록이 이어지지 않아, 처음 받을 때 처음 받은 판을 스스로 찾아 기준으로 잇는 커밋을 하나 더 만듭니다(파일은 바뀌지 않습니다). 그 판과 이 저장소의 첫 기록이 다른 파일은 이 저장소에서 고친 것으로 보고 그대로 둡니다. 그다음부터는 보통의 병합입니다.
- 옛 `vanilla/` 폴더판(1.0)으로 시작한 저장소도 그 판의 `vanilla/` 내용을 기준으로 합치므로, 양쪽이 실제로 같은 줄을 고친 파일만 충돌로 나옵니다. 이런 저장소에는 새 판 받기 도구가 없습니다. 배포 저장소 화면에서 `도구/업데이트.py` 파일을 열어 내려받기(Download raw file)로 받고, 내 저장소의 같은 자리(`도구/`)에 넣어 동기화한 뒤 `python3 도구/업데이트.py`(Windows는 `py -3 도구/업데이트.py`)로 받습니다.
- 클라우드 세션은 네트워크 설정에 따라 배포 저장소를 받지 못할 수 있고, 저장소를 기록 일부만 받아 오므로 얕은 복제로 멈출 수도 있으니 PC에서 합니다.
- 자세한 작동 방식은 사용설명서의 [새 판 받기](사용설명서.md#새-판-받기), 연습은 튜토리얼의 [9. 내 사무실 만들기와 새 판 받기](튜토리얼.md#9-내-사무실-만들기와-새-판-받기)에 있습니다.

## 무엇이 동기화되나
| 동기화됨 | 그 PC에만 남음 (`.gitignore`) |
|---|---|
| `.claude/` 업무기술서, `CLAUDE.md`, 안내 문서 | `안내실/`에 넣은 입력 파일 |
| `자료실/` 규칙·서식·교본·선례 | `산출물/` 건 폴더 |
| `라운지/` 오류노트(익명)·훈련기록·개선안, `라운지/훈련/`의 체크리스트 갱신안 | `발송실/` 승인본·.ics 파일 |
| `상황실/통합일정표.md` (확정 일정은 Google Calendar로도), `상황실/현안목록.md`(공개 키워드만), `상황실/대시보드.html`(화면만) | `상황실/브리핑/` (뉴스 브리핑 포함), 대시보드 데이터 파일 |
| | `라운지/훈련/`의 위임지시·훈련 문제·정답 |
| | 검토보고서 플러그인의 작업·입력 폴더(`_workspace/`, `입력/`), 인증키 파일 `.env` |
| | 직접 넣은 KISA 범피스 .exe(`도구/설치키트/payload/windows/`) |

- 전체 목록과 빼는 까닭은 `.gitignore`에 있습니다.
- 내 저장소는 **Private**으로 둡니다. 쓰다 보면 선례·오류노트·일정이 쌓이므로 Public으로 바꾸지 마세요([배포 저장소와 이용 조건](#배포-저장소와-이용-조건)).
- 비공개 선례는 파일명 앞에 `비공개_`를 붙이면 동기화에서 빠집니다.
- 산출물도 동기화하려면 `.gitignore`에서 `산출물/**` 줄을 지웁니다. 기관 보안 지침을 먼저 확인하세요. 그러면 건 폴더의 `_진행.md`(익명 ID와 건의 대응)도 올라가 오류노트의 익명이 풀립니다.

## PC마다 확인할 것
- **법령 MCP**: 국가법령정보 MCP는 이 배포본에 들어 있지 않아 직접 연결합니다. 검토보고서 플러그인이 권하는 것은 제3자 오픈소스 korean-law-mcp(https://github.com/chrisryugj/korean-law-mcp, npm `korean-law-mcp`, MIT)입니다.
  - 인증키: 법제처 국가법령정보 공동활용(open.law.go.kr)에서 OC 인증값을 각자 신청합니다. 키는 채팅창에 붙여 넣지 않습니다.
  - Claude Code: `/plugin marketplace add chrisryugj/korean-law-mcp` → `/plugin install korean-law@korean-law-marketplace`. 설치할 때 키를 묻습니다(`도구/설치키트/payload/AI-Assembly/plugins/bill-review/skills/bill-sources/SKILL.md` §1).
  - claude.ai·데스크톱 앱: 그 서버 README의 설치 안내를 따릅니다(claude.ai는 설정 → 커넥터의 커스텀 커넥터). 원격 서버를 쓰면 조회어와 키가 그 서버 운영자에게 갑니다(`면책고지.md` 5).
  - 연결 확인은 Claude Code에서 `/mcp`로 합니다. 연결이 없으면 원장을 만들 수 없습니다. 이때 조문 대조 검사기가 통과를 내더라도, 대비표를 만드는 팀(법제팀, 심사지원팀 소위자료, 법안검토팀 예비 경로)은 검증으로 넘기지 않고 멈춰 사람에게 묻습니다. 검토보고서 플러그인은 산출을 보류합니다. 다른 결과물의 법령 확인은 `[확인 필요]`로 남습니다.
- **설치키트 도구**: kordoc(HWP·PDF 읽기, HWPX 만들기)과 검토보고서 플러그인은 설치키트로 PC마다 설치합니다. 클라우드 세션에는 둘 다 없습니다. 그래서 법안검토팀은 설치키트 PC에서 이어 할지 이 세션에서 예비 경로로 할지 묻고, HWP 입력은 PDF로 바꿔 넣어야 합니다.
- **문서 스킬**: `bill-hwpx-autofill`, `amendment-comparison-table`, `참고조문`, `legislative-review`는 이 배포본에 들어 있지 않고 공개된 표준 스킬도 아닙니다. 쓰는 기관이 따로 마련해 계정에 둔 경우에만 쓰고, 없으면 그 파일(발의서 HWPX, 대비표·참고조문 DOCX 등)은 만들지 않고 마크다운으로 남기며 "도구 미연결로 ○○ 파일 미생성"이라고 알립니다. `xlsx`·`docx`·`pdf` 스킬은 계정에 있으면 씁니다(예결산 재계산 XLSX, PDF 읽기 등).
- **메일**: 메일 커넥터가 없으면 메일을 `안내실/메일/`에 .eml·.txt로 내보내 넣습니다.
- **Google Calendar**: claude.ai 설정 → 커넥터에서 Google Calendar를 연결하면, 상황실이 사람이 확정한 통합일정표 일정을 캘린더에 넣고 고칩니다(`/ops-desk 캘린더`). 일정은 공유하지 않는 전용 캘린더 하나에만 넣으니, Google Calendar에서 미리 만들어 두고 이름을 알려 주세요. 연결하지 않은 PC·세션에서는 `.ics` 파일을 만들어 드리니 Google Calendar 설정 → 가져오기로 넣습니다. 일정 제목 형식은 `상황실/통합일정표.md` 머리에 있습니다.
- **상급자 피드백**: 받은 피드백 파일을 `안내실/피드백/`에 넣고 "상급자 피드백 반영해 줘"라고 요청합니다. 이번 건을 보완하고, 채택한 항목은 검수 체크리스트가 되어 다음 건부터 검증 기준이 됩니다.
- **열린국회정보 API**: 인증키를 쓰려면 PC마다 `.env`에 `ASSEMBLY_KEY=…` 한 줄을 넣습니다(동기화되지 않음). `python3 도구/국회API점검.py`로 접속과 키를 확인합니다. 키 값은 출력하지 않고, 키가 없어도 한 번에 5건까지는 조회됩니다.
- **Python 3.8 이상**: 구성점검, 대시보드 갱신(`도구/대시보드갱신.py`), 메일 사본(`도구/메일사본.py`), 통합일정표 점검·.ics 만들기(`도구/일정내보내기.py`), 열린국회정보 API 점검(`도구/국회API점검.py`), 새 판 받기(`도구/업데이트.py`), 익명 ID 만들기, 조문 대조 검사기, 검증의 재계산에 씁니다. 없으면 대시보드, 새 판 받기, 상황실의 파일 메일·캘린더 처리와 조문 대조·예결산 검증을 할 수 없습니다.

## 진행 현황 대시보드
- 진행 현황 대시보드는 건 폴더의 `_진행.md`, 통합일정표, 현안목록, 오류노트·훈련기록, 검수 체크리스트를 한 화면에 모아 보여 줍니다.
- 저장소 폴더에서 `python3 도구/대시보드갱신.py`(Windows는 `py -3 도구\대시보드갱신.py`)를 실행한 뒤 `상황실/대시보드.html`을 더블클릭해 브라우저로 엽니다. Claude에게 "대시보드 갱신해 줘"라고 요청해도 됩니다.
- 화면은 인터넷 연결 없이 열립니다. D-n은 도구를 실행한 날 기준이므로 날이 바뀌면 다시 실행하고 새로 고칩니다.
- 데이터 파일 `상황실/대시보드_데이터.js`(있으면)는 건 내용을 담으므로 동기화하지 않고(`.gitignore`) 게시하지도 않습니다.
- 대시보드는 에이전트 기록을 모아 보여 줄 뿐입니다. 원문 대조와 최종 판단은 최종 검수자가 합니다(면책고지.md).

## 클라우드 세션 (claude.ai/code)
내 저장소를 선택해 세션을 시작하면 브라우저·모바일에서도 같은 팀을 씁니다. 세션 컨테이너는 끝나면 지워집니다. 업무기술서·자료실 변경은 커밋·푸시하고, `산출물/`의 건 폴더는 동기화 대상이 아니므로 이어 하려면 내려받아 두세요. 건은 같은 PC에서 이어 하고, 다른 PC에서 이어 하려면 건 폴더를 통째로 옮깁니다.
- 클라우드 세션에서 올린 변경은 세션 브랜치(`claude/…`, `ccr-…` 등)에만 들어가고 main에는 들어가지 않습니다. 다른 PC에서 받으려면 GitHub에서 그 브랜치를 main에 병합합니다. PR을 만들거나 병합하는 일은 사람이 하거나, 사람이 요청할 때 Claude가 합니다.
- **아침 뉴스 예약(선택)**: 기본으로 꺼져 있습니다. 매일 아침 뉴스 브리핑을 받으려면 `사용설명서.md`의 '아침 뉴스 예약'대로 발사대 세션 「뉴스 발사대」와 claude.ai 예약작업 「오늘의 뉴스」를 만들고, 실행 시각을 상황실 팀 설정의 '뉴스 예약 실행'에 적습니다.
  - 켜면 예약작업이 발사대 세션을 깨웁니다. 발사대는 실행마다 이 저장소를 붙인 새 클라우드 세션 「오늘의 뉴스 M월 D일」을 만들고, 그 세션이 main 최신으로 상황실 뉴스 모드를 무인으로 돌립니다. 실행마다 새 세션이라 한 세션에 대화가 쌓이지 않습니다.
  - 지난 날의 뉴스 세션은 세션 목록에 쌓이니, 필요 없으면 사람이 보관(archive)합니다.
- 클라우드 환경의 네트워크 설정에 따라 국회 의안정보시스템(likms.assembly.go.kr)·국회 입법예고(pal.assembly.go.kr) 같은 사이트가 막힐 수 있습니다. 세션 제목 줄의 환경 메뉴 → 편집 → 네트워크 접근에서 허용 도메인에 넣으면 열립니다(안내: https://code.claude.com/docs/en/cloud-environments#network-access). 막혀 있으면 뉴스 브리핑의 의안 확인이 `[확인 필요]`로 남습니다.

## 배포 저장소와 이용 조건
- 배포 저장소는 누구나 받을 수 있는 공개 저장소입니다(주소는 `배포판.md`). 쓰는 사람은 받아서 각자의 Private 저장소에 두고 씁니다([처음 쓰는 PC](#처음-쓰는-pc) 3).

- Fork를 권하지 않는 것은 쓰는 자료가 공개되지 않게 하려는 권고이고, GitHub의 기능으로 보고 포크하는 것 자체를 이용 조건이 막지는 않습니다(아래 '미리 허락을 받을 것'). 다만 포크는 공개되므로 쓰며 쌓은 자료를 올리는 데 쓰지 않습니다. 포크에 이미 자료를 올렸으면 사용설명서의 [문제 해결 (FAQ)](사용설명서.md#문제-해결-faq)을 봅니다.
