# release

법제업무 AI 에이전트 팀의 배포용 프로젝트를 모아 두는 저장소입니다. 각 폴더가 하나의 배포본이며, 쓰는 사람은 원하는 폴더를 자기 비공개 저장소로 옮겨 씁니다.

> **면책**: 이 저장소의 에이전트는 법제 실무의 초안 작성·자료 정리·점검을 돕는 보조 도구입니다. 결과물은 법률 자문이나 기관의 공식 의견이 아니며, 원문 대조와 사용 여부의 최종 판단·책임은 사람(최종 검수자)과 그 소속 기관에 있습니다. 자세한 내용은 각 배포본의 `면책고지.md`를 보세요.

## 배포본
| 폴더 | 판 | 무엇 | 시작 문서 |
|---|---|---|---|
| `vanilla/` | vanilla 1.0 (2026. 11. 5.) | 법제업무팀 에이전트 기본판: 8개 팀(상황실·법제·법안검토·예결산·조사·심사지원·뉴스레터·역량강화) + 진행 현황 대시보드. 기관 고유 자료를 모두 뺀 빈 사무실 | `vanilla/README.md` → `vanilla/튜토리얼.md` |

배포본의 바뀐 기록은 각 배포본의 `변경이력.md`(예: `vanilla/변경이력.md`)에 있습니다.

## 쓰는 법
1. `vanilla/README.md`의 '처음 쓰는 PC'대로 `vanilla` 폴더의 내용을 자기 **Private** 저장소의 맨 위로 옮깁니다.
2. 그 저장소 폴더를 Claude Code(또는 Claude 데스크톱 앱)로 열고 "구성 점검해 줘"라고 요청합니다.
3. `vanilla/튜토리얼.md`로 가상 예제를 한 번 돌려 본 뒤 실제 업무에 씁니다.

이 `release` 저장소 안에서 바로 Claude를 열면 배포본의 팀 설정(`.claude/`)이 읽히지 않습니다. 배포본 폴더를 따로 옮겨 여세요.

> **주의**: `release/vanilla` 폴더 안에서 Claude를 열거나 동기화(`동기화.sh`·`동기화.cmd`)를 돌리지 마세요. 그 폴더는 `release` 저장소의 하위 폴더라서, 연습 기록이 배포 저장소에 커밋될 수 있습니다. 동기화 스크립트는 자기 폴더가 git 저장소의 맨 위가 아니면 아무것도 올리지 않고 멈춥니다. 먼저 1번대로 폴더를 밖으로 옮겨 자기 저장소로 만듭니다.

## 정리 원칙
- 의안 원문, 선례 원문, 작성자·의원 실명, 계정·세션 정보, 운영 기록은 넣지 않습니다.
- 배포본이 쓴 안내 문서·서식·예제의 예시는 모두 가상 자료(○○법, 홍길동, `XXXXXXX`)로 씁니다.
- 예외: 제3자 구성요소인 검토보고서 플러그인(`vanilla/도구/설치키트/payload/AI-Assembly/`)은 `vanilla/제3자고지.md`에 적은 곳만 고치고 원본대로 두었습니다. 그래서 그 착안점 파일의 검토사례 색인에는 원저작자가 「법률안검토 표준교재」의 사례에서 옮긴 실제 법률안의 이름·대표발의 의원 이름·의안번호가, README와 LICENSE에는 원저작자의 저작권 표시·연락처가 들어 있습니다.
- 예외: 열린국회정보 점검 도구(`vanilla/도구/국회API점검.py`)의 기본 의안번호는 접속 확인용 공개 의안입니다.
- 제3자 구성요소의 라이선스는 각 배포본의 `제3자고지.md`에 적습니다.

## 라이선스
각 배포본 폴더의 `LICENSE`를 따릅니다. `vanilla/`는 내부 이용 허락입니다. 배포본을 받은 사람과 그 소속 기관은 자기 업무에 쓰려고 복제·수정해 비공개 저장소에 두고 쓸 수 있고, 기관 밖 제3자에게 넘기거나 공개하려면 배포자의 허락을 미리 받습니다. 제3자 구성요소는 각자의 라이선스를 따릅니다(`vanilla/제3자고지.md`).
